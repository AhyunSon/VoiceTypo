# 실험 01: 캘리브레이션 기반 모음 인식 파이프라인

담당: 서은 / 상태: 동작 검증 완료(화자 2명), 파라미터 튜닝 진행 중

## 1. 개요

사전학습 다화자 SVM 방식에서 **관람객별 즉석 캘리브레이션 방식**으로 전환한
음성 인식 파이프라인입니다.

- 기존 방식의 문제: 여러 화자의 녹음을 모아 하나의 범용 모델을 만들면,
  학습에 없던 새 화자에게 성능이 크게 떨어짐 (화자마다 성도 길이 등
  음향 특성이 다르기 때문)
- 전환한 방식: 관람객이 체험 시작 시 7모음(아·이·우·에·오·으·어)을
  3번씩 짧게 발성 → **그 자리에서 그 사람 전용 SVM을 학습** → 실시간 인식.
  화자 간 차이 문제가 구조적으로 사라짐

## 2. 파일 구성

| 파일 | 역할 |
|---|---|
| `calibrate.py` | 캘리브레이션 녹음 (7모음 × 3테이크 + 오/우 거리 스위프) |
| `calib_train.py` | 화자별 SVM 학습 + LOTO 품질 체크 + 마진 임계값 산출 |
| `calib_realtime.py` | 실시간 인식 스트림 (15ms 주기) |
| `check_calib.py` | 캘리브레이션 녹음 오프라인 재채점 (학습 정상 확인용) |
| `diag_live.py` | 라이브 발성 1회 녹음 → 오프라인 경로로 채점 (진단용) |
| `diag_compare.py` | 캘리브레이션 vs 라이브 MFCC 차이 분석 (진단용) |
| `feature_utils.py` | 공용 특징 추출 모듈 |

일반 사용은 위 3개(`calibrate` → `calib_train` → `calib_realtime`)만 쓰면 되고,
`check_calib`/`diag_*`는 인식이 이상할 때 원인을 찾는 진단 도구입니다.

## 3. 실행 환경

- Python 3.x
- 패키지 설치: `pip install numpy sounddevice soundfile scikit-learn`
- 마이크 필수. **노트북 내장 마이크 비권장** — 실측에서 내장 마이크는
  검증 수치가 75%대, 전용 마이크는 97%대로 차이가 컸습니다

## 4. 사용법 (단계별 상세)

### 4-1. calibrate.py — 녹음

```
python calibrate.py
```

1. 화자 이름 입력 (영어 권장, 예: `minji`)
2. 안내에 따라 모음마다 3테이크씩 녹음:
   - 테이크 1: 편한 피치, 평소 거리
   - 테이크 2: 조금 높은 피치, 마이크에 한 뼘 가까이
   - 테이크 3: 조금 낮은 피치, 마이크에서 한 뼘 멀리
   - (피치·거리를 함께 바꾸는 이유: 실전에서 일어날 변화를 모델에
     미리 보여줘서 인식을 강건하게 만들기 위함)
3. 마지막에 오/우 **거리 스위프** 2개: 4초간 발성을 유지하면서 마이크를
   천천히 가까이 → 멀리 이동 (오/우가 거리 변화에 특히 취약해서 추가 보강)
4. 무음이거나 발성이 너무 짧으면 자동으로 재시도를 요청합니다

- 저장 위치: `calib_wavs/<이름>/`
- ⚠ **같은 이름으로 다시 녹음하면 덮어씌워집니다.** 녹음본을 보존하려면
  `이름2`, `이름_mic` 처럼 구분해서 저장하세요

### 4-2. calib_train.py — 학습

```
python calib_train.py
```

녹음 때 쓴 이름을 입력하면 학습이 진행되고, 아래처럼 출력됩니다:

```
=== Leave-one-take-out 품질 체크 ===
  테이크 1 홀드아웃: 97.1%
  테이크 2 홀드아웃: 99.1%
  테이크 3 홀드아웃: 97.1%
  평균: 97.8%
최종 학습 완료: 1682개 프레임
마진 임계값(5퍼센타일): 0.9994
저장 완료: calib_model_<이름>.pkl
```

**LOTO(leave-one-take-out)가 뭔가요?**

3개 테이크 중 하나를 빼고 나머지 2개로 학습한 뒤, 뺀 테이크로 채점하는
검증입니다 (3번 반복). 모델이 "본 적 없는 발성"을 얼마나 맞추는지 보는
것이라서, 이 캘리브레이션이 쓸 만한지를 학습 직후 바로 알 수 있습니다.

- 테이크마다 피치·거리가 다르므로, 사실상 "피치와 거리가 바뀌어도
  인식되는가" 테스트입니다
- **읽는 법**: 평균 90% 이상 양호 / 70%대 이하면 재녹음 권장
  (특정 테이크만 유독 낮으면 그 조건에서 발성이 흔들렸다는 뜻)
- 실전 모델은 3테이크를 전부 사용해 학습하므로, 실제 성능은 LOTO
  수치보다 보통 높습니다 (LOTO는 일부러 하나를 빼는 스트레스 테스트)

**마진 임계값이 뭔가요?**

실시간 인식 때 "확신이 없는 판정"을 걸러내는 기준값입니다. 학습 데이터에서
자동 계산되며, 실시간에서 판정 확신도(margin)가 이 값보다 낮으면 모음을
표시하지 않고 `?` 처리합니다. 이상한 소리를 억지로 아무 모음에나 붙이는
것을 막는 안전장치입니다.

### 4-3. calib_realtime.py — 실시간 인식

```
python calib_realtime.py
```

학습 때 쓴 이름을 입력하고 발성하면 한 줄이 실시간으로 갱신됩니다:

```
raw:우(2등:오)  vowel:우  margin:1.42  f0:180Hz  rms:0.0710
```

**출력 항목 해설:**

| 항목 | 의미 |
|---|---|
| `raw` | 지금 이 순간(프레임)의 판정 결과. 떨림이 있을 수 있음 |
| `(2등:...)` | 판정 2순위 모음. 어떤 모음과 헷갈리고 있는지 확인용 |
| `vowel` | **안정화된 최종 라벨** — 시각화에 쓸 값. 흔들림 방지 처리(히스테리시스)가 적용되어 raw보다 차분하게 움직임 |
| `margin` | 판정 확신도. 임계값(대략 1.0)보다 낮으면 `?` 처리 |
| `f0` | 피치(기본주파수, Hz). 버블 상하 움직임용. 무성음이면 `---` |
| `rms` | 발성 세기. 버블 크기용 |
| `(무음)` | 소리가 없는 상태 |

- `raw`는 떨려도 `vowel`이 안정적이면 정상 동작입니다
- 박수·"쉬—" 같은 소리는 모음이 아니므로 `?` 처리됩니다 (의도된 동작)

**💡 마이크 거리 주의**: 입 기준 한 뼘 이내에서 가장 안정적입니다.
거리가 멀어지면 특히 '우' 인식이 급격히 나빠집니다 (아래 6번 참고).
거리를 바꿔가며 성능을 직접 확인해보세요.

## 5. 인식이 이상할 때 (진단 순서)

1. `python check_calib.py` — 캘리브레이션 녹음을 모델로 재채점.
   여기서 100% 안 나오면 학습 자체가 잘못된 것 (재학습/재녹음)
2. `python diag_live.py` — 문제 모음을 한 번 발성해 녹음하고 오프라인
   경로로 채점. **여기서도 틀리면** 실시간 코드가 아니라 발성/마이크
   조건이 캘리브레이션 때와 달라진 것 (마이크 거리·자세 확인, 또는 재캘리브레이션)
3. `python diag_compare.py` — 캘리브레이션 vs 방금 녹음의 MFCC 계수별
   차이(z-score) 출력. 저차 계수(C1~C4)가 크게 밀려 있으면 마이크
   거리/채널 변화가 원인

## 6. 운영 조건 (전시 셋업 요청 사항)

**마이크 근거리(입 기준 약 한 뼘 이내) 발성을 전제로 안정 동작합니다.**
원거리 발성 시 마이크 거리에 따른 스펙트럼 변화(저차 MFCC 이동)로
'우' 인식이 불안정해지는 것을 진단으로 확인했습니다.
전시 설치 시 **마이크 위치 고정 또는 발성 위치 안내**가 필요합니다.

## 7. 기술 요점 (구현 세부)

- 특징: 프레임 단위(15ms) MFCC 13차 + 델타 13차 = 26차, 프레임별 RMS 정규화.
  학습·실시간의 정규화 방식 통일 필수 (불일치 시 라이브 정확도 붕괴 사례 있음)
- 델타: 중앙 차분 (t+1 − t−1)/2. 실시간은 판정을 1프레임 지연시켜 동일 수식 유지
- F0: 간이 YIN(차이함수 + 누적평균정규화, numpy 벡터화). 60ms 창, 15ms 갱신
- 실시간 안정화: 유성음 게이트(F0 미검출 시 판정 제외) / 히스테리시스
  (새 라벨이 창의 60% + 연속 75ms 유지 시에만 교체, `?`는 교체 불가) /
  무음 시 라벨 초기화

## 8. 실측 결과 (내부 기준선)

> 동일 화자·마이크 조건의 프레임 단위 LOTO 값. 일반 성능 지표가 아닌 내부 비교용.

- 화자 1: 전용 마이크 **97.8%** / 노트북 내장 마이크 75.4%
- 화자 2: 전용 마이크 86.1% (스위프 없는 구버전 프로토콜)
