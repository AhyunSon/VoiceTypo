# 소리짓 · 비눗방울 (버블 구현 1차)

실시간 한국어 음성을 **비눗방울(버블)** 로 시각화한다.
사용자가 소리를 내면 발화 지점에 버블이 생겨 실시간으로 변형되고(FORMING),
발성이 끝나면 완성되어 위로 떠오르며(FLOATING), 화면 위에서 터진다(POPPING).

> 스택: TypeScript + React + Vite · HTML5 Canvas · Web Audio API · Pitchy v4 · 커스텀 스프링 물리 · 60fps RAF

---

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 — Start 버튼 후 마이크 허용
npm run build      # 타입체크(tsc) + 프로덕션 빌드
npm run typecheck  # 타입만 검사
```

마이크(getUserMedia)는 보안 컨텍스트에서만 동작한다. `localhost` 는 허용되므로 dev 로 접속하면 된다.

## 아키텍처 — 데이터 흐름

프롬프트 §3의 원칙을 그대로 코드 경계로 삼았다: **"오디오 원천은 파형 하나이며 모든 특징은 파생 스트림이다."**

```
입력 소스 (App 에서 선택)
  ├─ [마이크]  audio/AudioManager (파형)
  │     ├─ audio/PitchAnalyzer     → pitch, clarity
  │     ├─ audio/EnergyAnalyzer    → energy(RMS 0~1)
  │     └─ speech/VowelSource      → vowel, recognized   (포먼트 기반)
  └─ [인식기] speech/RemoteVoiceSource (WebSocket)
        └─ 파이썬 bubble_serve.py 의 {vowel, f0, rms} → 매핑
        ↓  어느 소스든 합쳐서 (매 25ms)
   types/audio.VoiceFrame  { time, pitch, clarity, energy, vowel, recognized }
        ↓
   detector/VoiceEventDetector.process(frame)   ← "프레임 간 비교"의 유일한 지점
        ↓  타입드 이벤트만 (types/events.VoiceEvent[])
   bubble/BubbleManager.handle(event)           ← 프레임 원시데이터 직접 참조 금지
        ↓  매 프레임(≈60fps) update(dt)
   render/BubbleRenderer.render(bubbles)
```

**경계 규칙(중요):** `VoiceFrame`(프레임 원시 데이터)을 읽는 것은 `VoiceEventDetector` 까지다.
`BubbleManager` 는 오직 `VoiceEvent` 만 구독한다. 이 분리 덕에 세기·길이·피치·떨림처럼
"프레임 간 변화"가 필요한 특징을 이벤트 하나로 캡슐화할 수 있다.

## 특징 → 시각 매핑 (각 특징은 직교하는 자유도 하나에만)

| 오디오 특징 | 이벤트 | 시각 자유도 | 구현 |
|---|---|---|---|
| 세기(RMS) — 미세 | `INTENSITY_CHANGED` | **세그먼트 크기(반지름)** | `energyToRadius` + 크기 스프링 |
| 세기(RMS) — 큰 변화 | `INTENSITY_SEGMENT` | **경계 없는 새 세그먼트(땅콩)** | 같은 모음 유지 중 작은 덩어리 + 큰 덩어리 (수정 4) |
| 길이(발음 지속) | (FORMING 중 누적) | **불투명도** | 세그먼트별 `heldMs` → `heldToOpacity`, 발성 종료 시 고정 |
| 피치(F0) — 생성 중 | `PITCH_SHIFT` | **세그먼트별 종횡비(모양)** | 활성 세그먼트 `aspect` 스프링, 높음=세로 길쭉/낮음=가로 넓적 (4차 수정 3) |
| 피치(F0) — 완성 후 | `UTTERANCE_END.pitchTrajectory` | **비행 y(수명 전체 부유)** | 궤적을 버블 수명 전체에 펼쳐 easeInOut 재생, 종료 후 감쇠 왕복/사인 부유로 계속 떠다님 (피치 부유 수정) |
| 떨림(피치 지터) | `UTTERANCE_END.tremor` | **이동 방향 수직축 진동** | FLOATING 에서 vel 수직 성분으로 `sin(swayPhase)·swayAmp` (수정 1) |
| 모음 | `VOWEL_RESOLVED`/`VOWEL_CHANGED` | **글자 + 세그먼트 경계** | 모음 바뀌면 경계선 있는 새 세그먼트 |

색상은 시각 자유도로 쓰지 않는다(비눗방울 틴트 고정, alpha 만 길이/터짐에 반응).
> 매핑(4차 확정): **세기 = 크기**, **피치 = 세그먼트별 종횡비(생성 중) + 비행 y 힌트(완성 후)**, **떨림 = 경로 흔들림**.
> 종횡비·크기는 **세그먼트 단위**로, 활성 세그먼트에만 적용되고 다음 세그먼트가 시작되면 동결된다 →
> 한 땅콩에 "납작한 아 + 홀쭉한 오"가 공존(4차 수정 3). 버블 완성 시 전체 시각 속성이 스냅샷 고정된다.

## 상태 머신

```
            UTTERANCE_START
   (없음) ───────────────▶ FORMING ──────────── UTTERANCE_END ─────────▶ FLOATING
                             │  ▲                                           │
              연달아 발성 START │  │ 병합 흡수 완료                             │ 랜덤 수명 만료
                    ┌────────┘  │                                           ▼
                 MERGING ───────┘                                        POPPING ──▶ (소멸)
                             │
      RECOGNITION_LOST(글자 있음): 글자 붕괴
                             ▼
                          DEBRIS ──▶ (소멸)
```

- **FORMING**: 제자리 고정. 실시간 피치·세기는 **활성 세그먼트에만** 종횡비·크기로 적용(위치 이동 없음). 세그먼트 간격은 매 프레임 `(rEff1+rEff2)×OVERLAP_RATIO`로 하드 클램프(떨어지지도 뭉개지지도 않음, 4차 수정 2). 새 세그먼트 시작 시 이전 세그먼트 동결, 완성 시 전체 고정(4차 수정 3).
- **MERGING**: 연달아 발성 시 방금 나온 가까운 버블에 새 세그먼트를 흡수(같은 모음→경계 없음, 다른 모음→경계 있음).
- **FLOATING**: 완성 후 **x는 랜덤 방향 표류 + 떨림**, **y는 피치 궤적을 수명 전체에 펼쳐 부유**(재생=수명×배율, easeInOut, 종료 후 감쇠 왕복/사인 부유로 정지 없음, 피치 부유 수정).
- **POPPING**: 터짐 정책(`popSettings`)에 따라 — 랜덤/고정 수명, 가장자리, 안 터짐. 3막 — 긴장 → 파열 → 잔여 입자.
- **DEBRIS**: 발성 도중 "크게 내고 있는데" 인식이 무너질 때만 글자가 낙하 잔해로(끝단 볼륨 감쇠는 붕괴 트리거 아님, 3차 수정 2).

> 터짐 파라미터(모드·수명·비율·가장자리)는 **런타임 튜닝 패널**(`config/popSettings` + `components/TuningPanel`)로 실행 중 조정한다(2차 수정 2).

## 인식 불가 처리 (프롬프트 §2-5)

- **발성 도중 인식 상실**(`RECOGNITION_LOST`, 글자가 이미 있던 경우): 글자가 무너져 아래로 쏟아지고(DEBRIS), 버블은 완성되지 않는다.
- **처음부터 인식 불가**: `App` 상단 토글로 두 안을 전환한다.
  1. `bubble-only` — 글자 없이 방울만 상승 후 상단에서 터짐.
  2. `bumpy` — 울퉁불퉁한 윤곽으로 떠다니다 **화면 가장자리**에서 터짐.
- **인식 지연 대응**: 버블을 먼저 null-vowel 로 스폰(spawn-then-detach, 스폰 스프링 오버슈트)하고,
  모음이 도착하면 `VOWEL_RESOLVED` 로 글자를 채운다. 너무 짧으면(false-start) 버블을 취소한다.

> 기각되지 않은 대안('?'만 / 가장 가까운 모음+'?' / 모래시계 소멸 / 작은 방울 흩어짐 / 추상 형태)은
> `types/bubble.ts` 의 `UnrecognizedMode` 주석에 확장 지점으로만 기록. 최종 단일안은 7/16 이후 재논의.

## 수정안 1차 반영 (5가지)

1. **완성 버블 랜덤 방향 확산** — 위로만 상승하던 것을 완성 시점 랜덤 방향 벡터(`velDir`)로 퍼지게. 위쪽 편향은 `SPREAD_UPWARD_BIAS`. 떨림은 이동 방향 **수직축**으로 일반화.
2. **피치 → 상하 위치** — 종횡비 대신 생성 중 버블의 수직 위치를 스프링으로 이동(높음=위). (보류였던 확장 지점 확정)
3. **정상 인식 발성은 종료 시 안 터짐** — 발성 종료 = 완성 → FLOATING. 터짐은 수명으로만.
4. **같은 모음 + 세기 변화 → 경계 없는 땅콩** — `INTENSITY_SEGMENT` 이벤트로 새 세그먼트 추가.
5. **랜덤 수명 터짐** — 완성 시 `POP_LIFETIME_MIN/MAX`에서 수명을 뽑아 그 자리에서 터짐. 가장자리는 반사(`EDGE_REFLECT`)/날아감.

## 수정안 2차 반영 (3가지)

1. **상하 이동을 완성 후로 + 세기 기반** — 생성 중에는 위치 고정(모양만 변형), 완성(FLOATING) 시 발성 평균 세기(`UTTERANCE_END.avgEnergy`)를 수직 속도 성분으로 변환해 랜덤 방향 위에 합성. 가중치 `ENERGY_TO_VERTICAL_WEIGHT`(0이면 순수 랜덤 비행).
2. **터짐 런타임 튜닝 패널** — 모든 터짐 파라미터를 가변 싱글턴 `popSettings`로 모으고, 화면 우하단 접이식 패널(`TuningPanel`)에서 실행 중 조정. 모드(랜덤수명/고정수명/가장자리/안터짐)·수명 범위·터짐 비율·가장자리 반사. JSON 복사 지원. 전시 모드에서는 `SHOW_TUNING_PANEL=false`로 숨김.
3. **피치 → 종횡비(모양)** — 피치를 다시 종횡비로. 높은 음=세로 길쭉(`sy>1`), 낮은 음=가로 넓적(`sx>1`), `ASPECT_MAX_DISTORT`로 클램프. 1차의 "피치→수직 위치" 코드는 제거.

## 수정안 3차 반영 (4가지)

1. **세그먼트 겹침 조정** — 중심거리를 `(r1+r2)×OVERLAP_RATIO`(기본 0.8)로 계산해 잘록한 허리가 보이는 땅콩. 경계 유무 무관, 3개 이상도 유지.
2. **끝단 인식 오붕괴 방지** — RECOGNITION_LOST 를 `RECOGNITION_LOST_MIN_ENERGY`(0.13) 이상일 때만 카운트. 발화 끝 볼륨 감쇠 구간의 포먼트 흔들림을 인식 실패로 오판하지 않음. 정상 인식 이력(`everRecognized`)이 있으면 종료 시 반드시 FLOATING. 비동기 소스용 `RECOGNITION_GRACE_MS` 상수 예비.
3. **비행 y = 피치 궤적** — 세기 기반 상하 이동 제거. 발성 중 피치 궤적을 0~1 정규화해 저장하고(`UTTERANCE_END.pitchTrajectory`), FLOATING 에서 `PITCH_TO_Y_PLAYBACK_S` 동안 y로 재생(올라간 만큼 위로). 재생 후 마지막 값 유지 + 랜덤 표류. x는 기존 유지.
4. **완성 버블 모양 고정** — 완성 시점에 종횡비·크기·스폰스케일 스프링을 스냅(`freezeVisuals`). 실시간 오디오/인식은 FORMING 버블에만 영향. 각 버블은 자기 데이터(세그먼트·고정 종횡비·피치 궤적)만 보고 그린다.

## 수정안 4차 반영 (3가지)

1. **비행 y 부드럽게** — 원시 피치 직접 반영 대신: (a) 스무딩 피치를 (b) 소수 키포인트(`TRAJECTORY_KEYPOINTS`)로 단순화하고, (c) y좌표를 궤적 "목표"로 삼아 스프링(`vSpring`)으로 간접 추종, (d) 수직 속도를 `MAX_VERTICAL_SPEED`로 하드 캡, (e) 진폭·재생시간(`pitchYRange`/`pitchYPlaybackS`)을 줄이고 길게 펴서 튜닝 패널에 노출. → 계단식·순간이동 제거, "둥실 떠올랐다 가라앉음".
2. **세그먼트 분리 방지** — 생성 시 1회가 아니라 **매 프레임** `layoutSegments`로 배치. 중심거리를 `(rEff1+rEff2)×OVERLAP_RATIO`(상한, 겹침 보장)와 `×MIN_SEPARATION_RATIO`(하한, 포개짐 방지) 사이로 클램프. `rEff`는 각 세그먼트 종횡비를 반영한 접합 축 실효 반지름. 세그먼트에 개별 물리 없음(비행·y·떨림은 버블 중심에만).
3. **세그먼트별 독립 모양** — 종횡비·크기를 버블 전체→세그먼트 단위로. 실시간 피치/세기는 활성 세그먼트에만, 새 세그먼트 시작 시 이전 세그먼트 동결. (모음 전환 디바운스 중에는 `PITCH_SHIFT`를 억제해, 곧 동결될 앞 세그먼트가 새 피치에 끌려가지 않게 함.) → "납작한 아 + 홀쭉한 오" 공존. 렌더러는 세그먼트별 타원으로 그린다.

## 수정안 5차 반영 (A부 버그수정 + B부 신규)

**A1 표류 미작동** — 버블마다 방향(randomSpreadDir)은 개별, 속도는 `[driftMin, driftMax]`에서 개별 랜덤. 반사 후 `driftMin` 하한 유지(정지 방지). `devLog` 플래그로 생성 로그. → 정지·일렬 대형 해소.
**A2 세그먼트 분리** — 배치(layoutSegments)는 매 프레임 실행(FLOATING 포함), 글자는 세그먼트 로컬 좌표에 고정. A1과 함께 "함께 움직이는 분리 쌍"의 주원인(유사 속도) 제거.
**A3 융합 실루엣** — 로브(경계 없는 연속 세그먼트)를 **오프스크린 캔버스에 합성** → 하나의 몸체 + 단일 외곽선(내부 원 교차 제거). 경계 있는 접합은 로브가 나뉘어 두 외곽선이 맞닿아 구분됨. *Canvas 2D 근사이며, 완성도는 예정된 SDF+matcap WebGL 렌더러로 대체 권장.*
**A4 불투명도** — `opacityMin`(기본 0.4)/`opacityMax`(0.95) 패널화, 하한 상향 → 짧은/긴 발성 구분.
**A5 종횡비** — 강도 `aspectStrength`(기본 0.55) 패널화 → 정지 화면에서도 납작/홀쭉 구분.
**A6 터짐 3막** — `popDurationS`(0.3~0.6) 비율 스케일. 긴장(수축·떨림)→파열(팽창·소멸)→잔여(입자).
**A7 동시 소멸** — 수명은 각 버블 완성 시점에 독립 샘플(전역 타이머 아님), 패널 변경은 기존 버블 소급 없음, Stop/종료가 일괄 제거하지 않음. 기본 수명 간격 넓힘(4~12s). *주 유발원은 A1(유사 속도로 가장자리 동시 이탈)일 가능성이 높아 함께 수정.*
**B1 하단 쌓임/소거** — 터짐·붕괴 글자 일부(`glyphStackRatio`)가 열 단위로 하단에 쌓이고, `stackClearAfterS` 경과 시 아래층부터 소거(`bubble/GlyphStack.ts`).
**B2 바닥/가장자리** — `edgeMode`(반사/통과) + `edgeBounce` 감쇠. 하단은 쌓임 높이 위에서 반사.
**B3 인식 오버레이** — `showOverlay` 플래그로 좌상단에 모음·인식여부·피치·에너지·최근 이벤트(타임스탬프) 표시(`RecognitionOverlay`).

> ⚠️ A1·A2·A7 은 근본원인 확정에 영상/로그가 필요해 진단 로깅(`devLog`, 오버레이)을 함께 넣었다. 다음 시연에서 재확인 대상.

## 피치 부유(浮遊) 수정

완성 후 y축 움직임을 "빠른 재생 후 표류"에서 "수명 전체에 걸친 느린 부유"로 교체.

1. **재생 시간 = 수명** — `trajDuration = 버블 수명 × trajectoryTimeScale`(기본 1.0). 궤적이 수명 내내 진행되어 '이동'이 아니라 '부유'로 보인다.
2. **속도 상한 하향** — `MAX_VERTICAL_SPEED`(상수) 제거, 패널 가변 `maxVerticalSpeed`(기본 34px/s)로. 수평 표류(`driftMin`)와 같은 자릿수.
3. **재생 종료 후 정지 금지** — `pitchIdleMode`로 (a) `pingpong`(삼각파 왕복 + 사이클마다 `pitchDecayRate` 진폭 감쇠) / (b) `bob`(마지막 y 유지) 선택. **미세 사인 부유(`idleBobAmp`, `IDLE_BOB_HZ`)는 항상 합성** → 재생이 끝나도, 피치가 평탄해도 잔잔히 오르내린다.
4. **easeInOut** — `sampleTrajectorySmooth`로 키포인트 전환에서 속도가 0에 가까워져 방향 전환(올라가다 내려가기)이 각지지 않는다. 스프링 간접 추종은 유지.
5. **튜닝 패널** — "피치 부유" 그룹에 재생 배율·수직 속도 상한·재생 종료 후 모드·왕복 감쇠율·부유 진폭 노출.

> y축에만 적용. 수평 랜덤 표류·떨림(5차 A-1)은 그대로 두고 합성한다.

## 세기 변화 감지 안정화 (어택·릴리즈 오탐 제거)

같은 세기·같은 모음으로 발성해도 어택(시작 상승)·릴리즈(끝 감쇠)가 세기 변화로 오탐돼
세그먼트가 여러 개 생기던 문제를 잡았다. 세그먼트 생성·렌더링은 그대로 두고,
**세기 변화 판정(INTENSITY_SEGMENT)만** 3단 조건으로 바꿨다. ([trackIntensity](src/detector/VoiceEventDetector.ts))

- **1) 상대(dB) 임계** — 절대 RMS 차이 대신 기준선 대비 `|20·log10(현재/기준선)| ≥ intensityChangeDb`(기본 6dB).
  기준선은 임계 미만일 때만 EMA(`INTENSITY_BASELINE_SMOOTHING`)로 갱신 → 느린 드리프트는 변화로 치지 않는다.
- **2) 유지 시간** — 임계를 넘은 수준이 `intensityHoldMs`(기본 180ms) 유지돼야 확정. 이 한 조건이
  어택(상승 중이라 유지 미성립)과 릴리즈(감쇠는 유지 전에 침묵→UTTERANCE_END)를 동시에 걸러낸다.
- **3) 후보 확정/흡수** — 임계를 넘으면 즉시 만들지 않고 후보(pending)로 두고, 유지 시간을 채우면 확정.
  채우기 전에 기준선으로 복귀하거나 발성이 끝나면 후보를 폐기해 직전 세그먼트에 흡수한다.
- **보조: 시작 유예** — 발성 후 `onsetGraceMs`(기본 120ms) 동안은 판정 없이 기준선 산출에만 쓴다.
  끝부분은 별도 자르기 없이 조건 2가 처리한다.
- 세기(에너지)에만 적용 — 모음 전환(VOWEL_CHANGED) 세그먼트 경로와 미세 변동 크기 보간(INTENSITY_CHANGED)은 그대로.
- **패널**: "세기 판정" 그룹에 `변화 임계(dB)`·`유지 시간(ms)`·`시작 유예(ms)` 노출.

검증: 헤드리스 **S16**(같은 세기 아–––, 어택·릴리즈 포함 → 세그먼트 1개), **S17**(약→강→약 → 3개),
기존 **S5**(약→강 → 2개, 땅콩) 유지. 모두 PASS.

## 버블 크기 동결 수정 (종료 후 축소 방지)

크게 낸 버블이 발성 종료 직후 다시 작아지던 문제를 잡았다. 원인은 크기 목표값이 매 프레임의
**순간 RMS** 에 바인딩돼, 릴리즈(끝 감쇠) 구간의 낮은 에너지가 종료 직전 크기를 끌어내리고
`UTTERANCE_END` 동결이 그 작아진 값을 고정한 것이었다.

- **크기 목표 = 세그먼트 기준 세기** — `INTENSITY_CHANGED` 가 순간 RMS 대신 **기준선
  (`segBaselineEnergy`, 세기 판정 안정화의 이동 평균)** 을 실어 보낸다. 어택·릴리즈·순간 출렁임에
  크기가 요동하지 않고, 세기가 실제로 달라졌을 때만 부드럽게 따라간다(창 크기는 `INTENSITY_BASELINE_SMOOTHING`).
  ([process 5b](src/detector/VoiceEventDetector.ts))
- **세그먼트 종료 시 동결** — 새 세그먼트가 붙으면 직전 세그먼트의 크기 스프링을 snap 한다
  (기존 `freezeSegment` 가 종횡비와 함께 크기도 이미 동결). ([appendSegment](src/bubble/BubbleManager.ts))
- **발성 종료 시 동결** — `UTTERANCE_END` → `freezeVisuals` 가 모든 세그먼트 크기를 snap.
  이후 침묵(에너지 0)은 크기에 영향을 주지 않는다. 크기 갱신은 `this.forming`(생성 중 버블)에만
  적용되므로, `FLOATING` 버블은 어떤 오디오 입력에도 크기가 변하지 않는다(완료기준 4).

검증: 헤드리스 **S18**(크게 아! → FLOATING 크기 유지 r≈60·동결 target=value), **S19**(작게 → r≈32 유지),
기존 **S10**(떠 있는 버블 불변). 부수 효과로 **S5**(약→강)의 세그먼트 크기 역전도 바로잡혔다. 모두 PASS.

## 세기 변화 속도 구분 — 확 커짐 vs 점점 커짐

같은 "커짐"이라도 급격한 변화와 점진적 변화가 다른 버블이 되게 했다. 세기의 **변화량**은 이미 크기에
매핑돼 있으므로, 이번엔 **변화 속도**를 **로브 개수**라는 별도 차원에 매핑한다 — 로브 개수가
"변화의 여정"을 기록한다(한 번에 건너뛰면 2개, 계단을 밟으면 밟은 만큼). ([trackIntensity](src/detector/VoiceEventDetector.ts))

- **변화 속도 분류기** — 슬라이딩 윈도우(`slopeWindowMs`, 300ms)로 세기 기울기(dB/창)를 잰다.
  - **급변**: 창 안 변화 ≥ `intensityChangeDb`(=SUDDEN_DB, 6dB) → 유지 시간 후 세그먼트 분할 1회 → **로브 2개**(기존 땅콩).
  - **점진**: 창당 변화 < SUDDEN_DB. 느린 드리프트는 기준선 EMA 가 흡수하되 **누적 dB**(마지막 로브 대비)를
    추적해, `gradualStepDb`(2.5dB)마다 현재 크기의 새 로브를 `hasBoundary:false`로 추가 → **로브 여러 개**.
    → 점진 변화가 이동 평균에 흡수돼 조용히 사라지던 문제를 해결. 로브 사이 `gradualStepMinMs`(150ms) 최소 간격.
- **감소 대칭** — 부호만 반대로 동일 적용(점점 작아짐 = 작아지는 로브 여러 개, 확 작아짐 = 큰 뒤 작은 로브 1개).
- **공존** — 재발성 딥 우선(딥 회복 시 점진 누적 리셋). 지속 하강은 딥이 아니라 수준 감소로 넘겨
  분할 1회. 점진 진행 중 급변이 오면 계단 로브들 위에 큰 로브가 허리로 이어진다.
- **글자 과밀 조절** — 로브가 많아 글자가 겹치면 `glyphEveryNLobes`(N로브마다 하나) 로 표시 간격 조절.
- **패널**: "변화 속도(급변/점진)" 그룹에 기울기 창·점진 단계(dB)·단계 최소 간격·글자 간격 노출.

검증: 헤드리스 **S23**(크레셴도 → 커지는 로브 5개), **S24**(데크레셴도 → 작아지는 로브 4개),
**S25**(점점 크게+확! → 계단 뒤 큰 로브), **S26**(단계 dB 3.0→4로브 vs 1.2→7로브),
회귀 **S5**(급변 2로브)·**S16**(일정 1로브)·**S20**(재발성 동일 크기). 모두 PASS.

## 재발성(음절 반복) 감지 — 피치 연속성 기반

"아아아"처럼 한 호흡 안에서 같은 모음을 반복하면 음절 수만큼 로브가 생겨야 하는데, 세기 안정화가
음절 사이 짧은 에너지 딥을 걸러내 로브가 안 생기던 문제를 잡았다. **신호 기준(팀 주파수 분석):**
연속 재발성은 음절 사이 에너지가 꺼져도 **피치 트랙이 이어지고**, 따로 발성한 "아, 아"는 피치가 끊긴다.
이 구분을 1급 기준으로 도입했다. ([VoiceEventDetector](src/detector/VoiceEventDetector.ts))

- **재발성 감지기 신설** (`trackReutterance`) — 에너지 딥(기준의 `dipRatio` 아래로 하강)이
  `dipMaxMs` 안에 회복하고, 딥 지속이 `dipMinMs` 이상이며, 딥 중 **피치 공백이 `pitchGapMaxMs` 이하**
  (피치 연속)이면 `SYLLABLE_REPEAT` 를 발행해 같은 모음의 경계 없는 로브를 **즉시**(유지 시간 없이) 붙인다.
  하강→회복(딥)과 상승→하강(스파이크)을 파형 방향으로 구분해 라우팅한다.
- **발성 경계에 피치 끊김 결합** — 종료를 에너지 침묵만이 아니라 **에너지 침묵 + 피치 소실**이
  `utteranceBreakMs`(딥 허용치보다 길게) 이상 지속될 때로 판정. → "아 (쉬고) 아"는 버블 2개,
  "아아아"는 버블 1개에 로브 3개.
- **두 감지기 공존** — 세기 수준 변화(dB+유지 시간)는 *수준이 달라지는* 변화(약→강 땅콩) 담당,
  재발성은 *같은 수준으로 되돌아오는* 딥 담당. 딥 중에는 수준 변화 **확정(발행)만 유보**해 재발성이
  우선하고, 회복 없이 눌러앉으면(딥 타임아웃) 그때 수준 변화로 확정한다.
- **패널**: "재발성(음절 반복)" 그룹에 딥 비율·딥 최소/최대·피치 공백 허용·발성 끊김 노출.

검증: 헤드리스 **S20**(아아아 → 로브 3개 한 버블), **S21**(아 쉬고 아 → 버블 2개),
**S22**(긴 아~~~ 떨림 → 로브 1개), 회귀 **S16**(같은 세기 1세그)·**S5**(약→강 땅콩)·**S17**(약→강→약 3세그, 공존). 모두 PASS.

## 다중 로브 렌더링 정리 — 접합부 쐐기 근절

로브 3개 이상에서 접합부마다 흰 쐐기/삼각형이 실루엣을 가르던 문제를, 원인 코드를 **삭제**하고
실루엣을 오직 알파 마스크 union 으로만 만들도록 재작성해 근절했다.

- **지시 1 — 접합부 채우기 삭제**: 실루엣 가장자리를 침식-빼기(`destination-out` 0.9배 union)로
  만들던 rim 을 제거했다. 이게 접합부 오목부에 색을 남겨 쐐기/슬리버의 원인이었다.
  (코드베이스에 접합부 다각형 fill 이 남아 있지 않음 — grep 확인.)
- **지시 2 — 알파 마스크 union 만**: 버블당 오프스크린에 모든 로브를 **변형 후 실제 타원**으로
  단색 알파 채우기(union) → 3개 이상이면 작은 블러 → 임계값(`silhouetteBlurPx`)으로 접합부만
  매끈하게(허리 보존). 그 마스크 안(`source-in`/`source-atop`)에만 몸체 그라디언트·로브별
  하이라이트를 그린다. `hasBoundary` 접합부는 렌즈 교차 중심선을 **가는 스트로크 곡선 1개**로
  (면 채우기 아님; 계산 불가 프레임엔 안 그림). 글자는 마지막에 마스크 위에.
  ([drawSilhouette·membraneChord](src/render/BubbleRenderer.ts))
- **지시 3 — 비인접 로브 이격 + 되접힘 방지**: 모든 생성 경로가 거치는 `layoutSegments` 에
  비인접 쌍 최소 이격 PBD(`NONADJ_SEPARATION_RATIO`)를 재적용하고, 부착 방향을
  **직전 방향 ±`ATTACH_ANGLE_JITTER`(±60°)** 로 제한해 체인이 고리로 되접히지 않게 했다
  (되접힘 고리가 큰 실루엣 틈의 원인이었다). ([layoutSegments](src/bubble/BubbleManager.ts))

검증(헤드리스 라스터 시뮬 `scratchpad/*.mjs`): 실제 배치(±60° 제한 + PBD)로 3·4·5·6·8 로브를
각 300회 랜덤 시행 → 블러 후 실루엣 **틈 발생률 0%**. 절대 랜덤 각(제한 없음)은 8로브에서 67%가
틈이 생겨, 되접힘 제한이 필수임을 확인. 로직 하니스 29/29 유지(S11·S13 은 실제 접합 축 기준으로 갱신).
(최종 화면 아티팩트 없음은 브라우저 확인 항목.)

## 렌더링 성능 정리 (렉 제거)

union 도입 후 매 프레임 오프스크린 재합성·블러·getImageData 로 프레임이 무너지던 문제를,
**동결 버블 스프라이트 캐싱 + 로브별 독립 경로 union** 으로 정리했다. ([BubbleRenderer](src/render/BubbleRenderer.ts))

- **스프라이트 캐싱(핵심)**: `FLOATING` 버블은 시각 속성이 동결되므로 **완성 시 1회** 오프스크린에
  최종 합성(실루엣+그라디언트+하이라이트+경계막+글자)해 스프라이트로 굽고, 이후 매 프레임엔
  `drawImage` 로 위치·불투명도만 찍는다. 매 프레임 실시간 합성은 **FORMING 1개뿐**. 터짐(POPPING)은
  스프라이트를 scale·alpha 로 변형만 한다(재합성 없음). → 비용이 "버블 수 × 합성"에서
  "완성 합성 1회 + 버블 수 × drawImage" 로.
- **실시간 블러 제거 + 로브별 독립 경로**: 매 프레임 `ctx.filter='blur'`·`getImageData` 제거.
  실루엣은 **로브마다 `beginPath()`→`ellipse()`→`fill()`(불투명) 을 쌓은 union** 으로만 만든다.
  한 경로에 ellipse 를 누적하면 Canvas 가 호 사이에 직선 연결선을 넣어 "직선 변 부채꼴"과 winding
  상쇄 틈이 생기므로(라스터 시뮬: 8로브 40/40 케이스에서 초과채움 ~24k·틈 ~21k px), 로브를 각각
  독립적으로 그려 쌓는다(겹침이 곧 union, 틈·부채꼴 구조적으로 불가). 이 union 을 오프스크린
  알파 버퍼로 만든 뒤 `source-in` 으로 몸체 그라디언트를, `source-atop` 으로 하이라이트·경계막을 넣는다.
- **프레임당 재계산·할당 제거**: 세그먼트 스프링·`layoutSegments`(O(로브²) PBD) 재계산을
  **FORMING/MERGING 버블만** 수행하고, 완성 버블 배치는 freeze 시점에 1회 확정한다
  ([update·beginFloating](src/bubble/BubbleManager.ts)). 오프스크린 캔버스도 프레임당 생성하지 않는다.
- **계측**: 튜닝 패널 상단에 FPS·프레임시간(ms)·프레임시간 스파크라인(16ms 목표선). ([PerfMeter](src/components/PerfMeter.tsx))

관찰 노트(우하단 글자): **글자-버블 분리가 아니라 의도된 B1 글자 쌓임**이다 — 터진 버블의 글자가
화면 하단(그 버블의 x 열)에 쌓여 `stackClearAfterS` 후 사라진다. 글자는 이제 스프라이트 안에
함께 베이크되어 렌더러가 버블과 글자를 분리해 그릴 수 없다. (원치 않으면 튜닝 "글자 쌓임" 해제.)

검증: 로직 하니스 29/29. 화면 FPS(버블 10개+FORMING 1개 60fps, 완성 버블 늘어도 프레임시간 불변)는
튜닝 패널 계측으로 브라우저에서 확인하는 항목.

## 음성 인식 연결 (파이썬 인식기 → WebSocket)

별도 프로젝트 `../음성 인식`(캘리브레이션 기반 모음 인식, 파이썬)을 입력 소스로 붙였다.
브라우저는 OSC/UDP 를 직접 받을 수 없어 **WebSocket** 으로 잇는다.

- **파이썬 쪽**: `recognizer.py`(인식 코어, 제너레이터)를 `calib_realtime.py`(콘솔)와
  `bubble_serve.py`(WebSocket 송출)가 공유한다. `bubble_serve.py` 가 프레임(15ms)마다
  `{vowel, margin, f0, rms, silence}` 를 브로드캐스트한다.
- **브라우저 쪽**: `speech/RemoteVoiceSource.ts` 가 접속해 최신 페이로드를 VoiceFrame 으로
  합성한다 — `pitch←f0`, `energy←rms/ENERGY_REFERENCE`, `vowel←vowel('?'/무음이면 null)`.
  이후는 기존 파이프라인(Detector→Manager)과 **완전히 동일**. 경계 규칙도 유지된다.
- **소스 전환**: 상단 툴바 "입력" 셀렉트(`마이크` ↔ `인식기(WS)`). **기본값은 `인식기(WS)`**
  (`useBubbleVisualizer` 의 초기값) — 앱을 켤 때마다 파이썬 인식기로 시작하므로 먼저
  `bubble_serve.py` 를 띄워야 한다. 인식기 모드에선 브라우저 마이크를 열지 않고, 연결 상태를
  HUD 에 표시한다. 스트림이 끊기면(`REMOTE_STALE_MS` 초과) 무음 프레임으로 전환한다.
  (서버 없이 바로 보려면 입력을 `마이크`로 바꿔 브라우저 포먼트 인식으로 폴백.)
- **주소**: `config/bubbleConfig.ts` 의 `REMOTE_WS_URL`(기본 `ws://localhost:8765`).
  다른 PC 에서 인식기를 돌리면 그 PC 의 IP 로 바꾼다.

실행: `음성 인식/README.md` 10절 참고 (`pip install websockets` → `python bubble_serve.py`).

## 조작

`Start` 후 소리를 내면 모음(아·어·오·우·으·이·에)이 버블이 된다.
- 세게 → 커지고, 오래 → 진해지고, **높게 → 세로로 길쭉 / 낮게 → 가로로 넓적**(활성 세그먼트 모양만 변형, 위치 고정).
- 같은 모음이라도 세기를 크게 바꾸면 경계 없는 땅콩(작은+큰 덩어리)이 된다.
- "아(낮게)→오(높게)"처럼 내면 **납작한 아 + 홀쭉한 오**가 한 땅콩 안에 각자 모양으로 공존한다.
- 발음 중 모음을 바꿔도 세그먼트는 떨어지지 않고 잘록한 허리로 이어진다.
- 발성을 멈추면 완성되어 날아가고, **비행 중 y는 발성했던 피치 흐름을 따라 부드럽게** 떠올랐다 가라앉는다.
- 완성된 버블은 새로 다른 소리를 내도 모양·글자가 바뀌지 않는다.
- 터짐 타이밍/모드/비율은 우하단 **터짐 튜닝 패널**에서 실행 중 바꿀 수 있다.
